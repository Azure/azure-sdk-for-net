# Custom Back-Compat Code That Could Be Replaced By Generated Code

Analysis report — follow-up to [PR #62393 "Replace Custom Back Compat Code with Generated Code - Part 2"](https://github.com/Azure/azure-sdk-for-net/pull/62393).

## 1. Scope and method

* **Reference baseline:** all 523 files touched by PR #62393 were downloaded and classified to build a catalogue of "custom back-compat code the generator can now emit itself".
* **Search space:** every library under `sdk/` that has a `tsp-location.yaml` (i.e. is generated from TypeSpec) — 311 packages, of which 226 are `Azure.ResourceManager.*` management-plane packages.
* **Only non-generated code was considered.** Any file under a `Generated/` folder was excluded; only `Custom/`, `Customization/`, `Customized/`, `Customize/`, `Compatibility/` and equivalent hand-written folders under `src/` were scanned.
* **Excluded from the results** (already covered by PR #62393):
  `Azure.ResourceManager.ScVmm`, `Azure.ResourceManager.Billing`, `Azure.ResourceManager.Cdn`, `Azure.ResourceManager.Compute`, `Azure.ResourceManager.Consumption`, `Azure.ResourceManager.CosmosDB`, `Azure.ResourceManager.DataFactory`, `Azure.ResourceManager.FrontDoor`, `Azure.ResourceManager.IotOperations`, `Azure.ResourceManager.Monitor`, `Azure.ResourceManager.RecoveryServicesSiteRecovery`, `Azure.ResourceManager.Redis`, `Azure.ResourceManager.ServiceFabric`, `Azure.ResourceManager.Storage`.

## 2. Pattern catalogue derived from PR #62393

These are the shapes the PR proved are now (or soon will be) generator-owned. They are the detection signals used throughout this report.

| ID | Pattern | Example removed by #62393 |
| --- | --- | --- |
| **P1** | `protected X() { }` shims re-added on `public abstract partial class` discriminator base models, because the generator emitted only `private protected` ctors (ApiCompat `CannotSealType`). | `RecoveryServicesSiteRecovery/src/Custom/Models/DiscriminatorBaseShims.cs` (330 lines, ~40 types), `Cdn/.../DeliveryRuleAction.cs` |
| **P2** | `[EditorBrowsable(EditorBrowsableState.Never)]` compatibility overloads on `*Resource` / `*Collection` / `*Extensions` / `Mockable*` types that simply forward to the current generated overload. | `Monitor/src/Customization/Compatibility/MonitorPrivateLinkScopedResourceCollection.cs`, `Compute/src/Customize/VirtualMachineCollection.cs` |
| **P3** | `[CodeGenSuppress("Tags")]` + manual re-declaration to work around duplicated `[WirePath]` attributes (`enable-wire-path-attribute`, issue #59545). | `Billing/src/Custom/Models/BillingAccountPatch.cs` (×4) |
| **P4** | Custom `Arm*ModelFactory` partials restoring legacy factory overloads. | `Cdn/src/Customization/ArmCdnModelFactory.cs`, `CosmosDB/src/Custom/ArmCosmosDBModelFactory.cs` |
| **P5** | Files carrying `// <auto-generated/>` inside a *custom* folder — verbatim copies of generated files (usually paired with `Compile Remove`) kept only to change member visibility. | `Storage/src/Customize/FileServiceUsageData.cs` ("Backward-compat (Compile Remove replacement)") |
| **P6** | `{Resource}Patch` / property partials restoring names now handled by the generator's auto-rename and `@@alternateType`/`clientName` support. | `Cdn/.../FrontDoorOriginPatch.cs`, `DataFactory/src/Customized/Models/*` (~750 files) |
| **P7** | Custom `*Extensions` static pass-throughs (`[CodeGenSuppress]` + long-named duplicates) preserving baseline extension-method names. | `FrontDoor/src/Customized/FrontDoorExtensions.cs` |

## 4. Highlights per top candidate

### 4.1 Highest-value: P1 abstract-base constructor shims (exact `DiscriminatorBaseShims.cs` analogue)

This is the single most mechanical, highest-confidence category — PR #62393 deleted a 330-line file of these from `RecoveryServicesSiteRecovery` because the generator now emits `protected` parameterless constructors on abstract discriminator bases. The same code still exists, one-file-per-type, in:

| Library | Shim files | Marker comment used |
| --- | ---: | --- |
| `Azure.ResourceManager.MachineLearning` | 35 | `// Customized: restore protected constructors for legacy extensible base models that customers may subclass; TypeSpec generation does not emit these non-wire constructors.` |
| `Azure.ResourceManager.RecoveryServicesBackup` | 17 | `// NOTE: The following customization is intentionally retained for backward compatibility.` |
| `Azure.ResourceManager.DataMigration` | 15 | `// Backward-compat justification: restore the GA-era protected constructor suppressed by the new generator for ApiCompat.` |
| `Azure.ResourceManager.DataProtectionBackup` | 12 | same "intentionally retained" marker |
| `Azure.ResourceManager.RecoveryServicesDataReplication` | 10 | same |
| `Azure.ResourceManager.SecurityCenter` | 9 | `// Compatibility customization …` |
| `Azure.ResourceManager.DataBox` | 7 | — |
| `Azure.ResourceManager.Avs`, `Azure.ResourceManager.Network`, `Azure.ResourceManager.ServiceFabricManagedClusters` | 4 each | — |
| `Azure.ResourceManager.AlertsManagement`, `Azure.ResourceManager.StorageMover` | 3 each | — |
| `Azure.ResourceManager.SecurityInsights`, `Azure.ResourceManager.WorkloadOrchestration` | 2 each | — |
| 12 further libraries | 1 each | `OracleDatabase`, `Authorization`, `BotService`, `Chaos`, `CognitiveServices`, `CostManagement`, `EdgeOrder`, `EventGrid`, `MigrationDiscoverySap`, `MongoCluster`, `MySql`, `Quota`, `RecoveryServices`, `AppContainers` |

**Total: ~145 shim files across 26 libraries.** Every one is a single `protected X() { }` inside `public abstract partial class X` and should disappear on regeneration with no API-surface change.

### 4.2 `Azure.ResourceManager.Sql` (sqlmanagement) — 345 `EditorBrowsable(Never)` members
* `src/Custom/Extensions/{SqlExtensions,MockableSqlArmClient,MockableSqlResourceGroupResource,MockableSqlSubscriptionResource}.cs` — the exact **P7** shape removed from FrontDoor: `[CodeGenSuppress]` + hand-written long-named extension pass-throughs.
* 19 files reference [azure-sdk-for-net#59990](https://github.com/Azure/azure-sdk-for-net/issues/59990) (*multi-path resources return the wrong Resource type*), 6 reference #60037, 4 reference #60105. The issue text explicitly says *"Currently, this issue can be mitigated through customization code. However, it should be handled by CodeGen"*. **Still open** — track, don't delete yet.
* **Caveat:** `src/Custom/2014-04-01/**` (32 files) are `[Obsolete]` deprecated API-version types that are no longer in the spec. These are *not* replaceable by generation and should be left alone.

### 4.3 `Azure.ResourceManager.NetworkCloud` (networkcloud) — 349 `EditorBrowsable(Never)` members, 67 files marked "intentionally retained for backward compatibility"
* `src/Custom/Extensions/MockableNetworkCloudSubscriptionResource.cs` and `NetworkCloudExtensions.cs` are pure **P2/P7** forwarding overloads (`GetNetworkCloudBareMetalMachinesAsync(CancellationToken) => GetNetworkCloudBareMetalMachinesAsync(null, null, ct)`) — identical to the Compute/Monitor overloads deleted in #62393. These are generatable today via optional-parameter back-compat overload emission.
* 13 `src/Custom/Models/*` partials (`ExtendedLocation`, `NetworkAttachment`, `*Patch`) are **P6** name/shape restorations.
* `src/Custom/Models/NetworkAttachment.cs` is a **P5** `<auto-generated/>` copy.

### 4.4 `Azure.ResourceManager.AppService` (websites) — 235 custom files, 295 `EditorBrowsable(Never)` members
* Split across `Customization/AppService` (124), `Customization/DomainRegistration` (58), `Customization/CertificateRegistration` (52).
* Explicit "Compatibility shim: GA 1.5.0 exposed `WebSiteResource.GetAllCo…`" markers — classic **P2**.
* 4 files reference [#43813](https://github.com/Azure/azure-sdk-for-net/issues/43813), 3 reference [autorest.csharp#4798](https://github.com/Azure/autorest.csharp/issues/4798), 1 references [typespec#11708](https://github.com/microsoft/typespec/issues/11708) (`GetCallbackUrl` → `GetCallbackUri` rename guard) and 1 references [typespec#11667](https://github.com/microsoft/typespec/issues/11667).
* 4 custom `*ModelFactory` partials (**P4**).
* `Customization/AppService/Models/ResourceMetricDefinition.Serialization.cs` is a **P5** generated-file copy.

### 4.5 `Azure.ResourceManager.Network` (network) — 620 custom files, 229 with `CodeGenSuppress`, 82 with removal TODOs
Largest custom-code surface in the repo and the most generator-blocked:
* **77 files** carry `// TODO: Remove this SDK-side workaround …` pointing at [azure-sdk-for-net#60023](https://github.com/Azure/azure-sdk-for-net/issues/60023) — *"Network MPG generated code requires analyzer allowlist for hidden inherited members and obsolete compatibility references"* (CS0108/CS0114/CS0618). **Open**; the fix would let `eng/analyzerallowlist/Azure.ResourceManager.Network.txt` and these 77 files be deleted together.
* `src/Customization/ConnectionMonitorContent.RemainingSetterCompatibility.cs` uses `[CodeGenSuppress("Location")]` + `[CodeGenSuppress("Tags")]` — the same envelope/flatten collision as the **P3** Billing `WirePath` workaround removed in #62393.
* 9 "Compatibility setter: previous GA surface was settable; generator emits getter-only" partials — generatable via `@@visibility`/`clientName` on the spec side.
* Additional `typespec#11696` (×2) and `typespec#11708` (×1) rename-guard workarounds.

### 4.6 `Azure.ResourceManager.MachineLearning` (machinelearningservices)
* 35 **P1** shims (see 4.1) — the biggest single cluster in the repo.
* 30 files use `CodeGenSuppress`; 6 files carry `// TODO: Remove this workaround` referencing [typespec#11696](https://github.com/microsoft/typespec/issues/11696) (*acronym normalization ignores ApiCompat contracts* — `PrivateIpAddress`, `PublicIpAddress`, `HostIp`, `OsVhdSizeMB`, `IsLatestOsImageVersion`). **Open.**
* 1 file references [#60130](https://github.com/Azure/azure-sdk-for-net/issues/60130).

### 4.7 `Azure.ResourceManager.ApiManagement` (apimanagement) — 225 `EditorBrowsable(Never)` members from 40 files
* Densest **P2** ratio in the repo (5.6 hidden members per custom file).
* 5 files reference [#60083](https://github.com/Azure/azure-sdk-for-net/issues/60083), 2 reference #60079, 1 references #60066.
* 1 file references [#56996](https://github.com/Azure/azure-sdk-for-net/issues/56996) (HEAD → `CheckExistence`) — see §5.
* 2 **P5** generated-file copies: `Customized/Models/ApiManagementContentType.Serialization.cs`, `Customized/Models/ApiRevisionContract.cs`.

### 4.8 `Azure.ResourceManager.SecurityCenter` (securitycenter)
* 202 **P2** members across 219 custom files, plus 9 **P1** shims.
* "Compatibility customization" ×10, "Compatibility shim: the legacy flattened …", "Compatibility shim: TypeSpec cannot …" — mostly **P6** flatten restorations that `@@flattenProperty` / `clientName` can now express in `client.tsp`.
* 1 file references [typespec#11588](https://github.com/microsoft/typespec/issues/11588).

### 4.9 `Azure.ResourceManager.ContainerRegistry` (containerregistry)
* 125 **P2** members; 79 of the 88 custom files live under `src/Custom/ContainerRegistry.Tasks` — deprecated Task/Run model re-exports plus `// Backward compatibility: ModelFactory methods for deprecated Task/Run …` (**P4**).
* Sibling package `Azure.ResourceManager.ContainerRegistry.Tasks` has 3 files blocked purely on [typespec#11708](https://github.com/microsoft/typespec/issues/11708) (`GetLogSasUrl`/`GetBuildSourceUploadUrl` → `…Uri`). Once that guard is fixed these 3 files delete cleanly.

### 4.10 Other notable clusters
* **`Azure.ResourceManager.ManagedNetworkFabric`** — 216 **P2** members. *Mixed*: 11 "Backward compatibility shim for the TypeSpec migration" and 9 "adds back a previously safe flattened property" members throw `NotSupportedException` (deliberate deprecation stubs, **not** replaceable), but 6 files are pure [typespec#11707](https://github.com/microsoft/typespec/issues/11707) rename guards that are.
* **`Azure.ResourceManager.NetApp`** — 178 **P2** members; "Backward-compat: GA exposed …", "GA shipped `CustomThroughputMibps` as `float?`" → candidates for `@@alternateType` in `client.tsp` rather than C# partials, matching the DataFactory approach in #62393.
* **`Azure.ResourceManager.DnsResolver`** — 80 **P2** members concentrated in 3 repeating shapes: "old `CreateOrUpdate` took string" (×10), "old `Delete`/`DeleteAsync`" (×10), "old `Update`/`UpdateAsync`" (×9). Highly mechanical; plus "Backward-compatibility shims: preserve the AutoRest model factory overloads" (**P4**).
* **`Azure.ResourceManager.Hci`** — 139 **P2** members, mostly "Backward-compat type alias" partials; a spec-side `@@clientName` should replace most of them.
* **`Azure.ResourceManager.Automation`** — 116 **P2** members plus a workaround for [typespec-azure#4729](https://github.com/Azure/typespec-azure/issues/4729).
* **`Azure.ResourceManager.PolicyInsights` / `PrivateDns` / `Dns`** — 10/12/17 `CodeGenSuppress` files each with modest **P2** counts; small, self-contained clean-up batches.
* **`Azure.ResourceManager.HybridConnectivity` (5), `RecoveryServices` (4), `Peering` (4), `KeyVault` (3), `Sql` (3), `ImpactReporting` (3)** — the **P5** "generated file copied into a custom folder" pattern, the exact shape of `Storage/src/Customize/FileServiceUsageData.cs` removed in #62393. These are the cheapest wins: verify the generated visibility now matches, then delete the copy and its `Compile Remove`.

## 6. Explicitly *not* candidates

Flagged during the scan so they are not mistakenly batched in:

1. **`Azure.ResourceManager.ManagedNetworkFabric` deprecation stubs** — properties whose getters/setters `throw new NotSupportedException("… Use X instead.")`. Deliberate `[Obsolete]` surface, not generator output.
