# TypeSpec source for storage models

`main.tsp` is the formal TypeSpec contract for the Foundry State Storage wire
API (`/storage/state_stores/*`), companion to the prose spec
`foundry-state-storage-provider-spec.md` in `coreai-microsoft/foundrysdk_specs`.

It is the source of truth for the generated request/response model classes
under `../src/Storage/Generated/` (`StateStore`, `StateStoreItem`,
`CreateStateStoreRequest`, etc.) — those files carry an `<auto-generated/>`
header and should only be changed by re-running generation, not by hand.

## Why this isn't synced via `tsp-client` (yet)

Sibling packages like `Azure.AI.AgentServer.Responses` generate models by
running `tsp-client` against a `tsp-location.yaml` pointing at a directory
under `Azure/azure-rest-api-specs`
(`specification/ai-foundry/data-plane/Foundry/src/...`). This contract does
not live there yet — there is no `state-stores` directory upstream. Until it
is published there, `main.tsp` is authored and compiled locally.

Once it lands upstream, replace `main.tsp` with a `tsp-location.yaml`
pointing at the new `specification/ai-foundry/data-plane/Foundry/src/state-stores`
directory and switch to the standard `tsp-client` + compile flow, matching
`Azure.AI.AgentServer.Responses`.

## Regenerating models

From this `type_spec/` directory:

```
npm install            # one-time: install the pinned TypeSpec toolchain
npx tsp compile main.tsp
```

This runs the `@typespec/http-client-csharp` emitter and writes to
`tsp-output/src/Generated/`. Copy the `Models/`, `Internal/`, and
`AzureAIAgentServerCoreStorageModelFactory.cs` outputs into
`../src/Storage/Generated/`, discarding the generated client/operations code
(`StorageClient*`, `StateStores*`, `StateStoreItems*`, options/settings, and
the `schema/` directory) — this package builds its own requests by hand in
`FoundryStateStore`; only the model classes are used.

### Post-generation: make the wire-only models `internal`

The emitter marks every model `public`. The request/error/list-envelope
wire types are implementation details (they never appear on a `FoundryStateStore`
method signature — requests are built and responses wrapped by hand), so after
copying, flip these eight types (both `Models/<T>.cs` and
`Models/<T>.Serialization.cs`) and their `AzureAIAgentServerCoreStorageModelFactory`
factory methods from `public` to `internal`:

`CreateItemRequest`, `PutItemRequest`, `CreateStateStoreRequest`,
`UpdateStateStoreRequest`, `ApiError`, `ApiErrorResponse`,
`ListResponseStateStore`, `ListResponseStateStoreItemKey`.

The public model surface is then just `StateStore`, `StateStoreItem`,
`StateStoreItemRef`, `StateStoreItemKey`, `DeletedStateStore`,
`DeletedStateStoreItem`, and the `ListRequestOrder` enum. (`list_keys` returns
the hand-written `StateStoreItemKeyPage` wrapper over the internal
`ListResponseStateStoreItemKey` envelope.) The upstream way to express this is
the `@access(Access.internal)` decorator from
`@azure-tools/typespec-client-generator-core`; it is applied as a copy-time step
here to avoid pulling the full Azure TypeSpec stack into this local-only
generation project.

`node_modules/` and `tsp-output/` are generation artifacts and are
git-ignored; only `main.tsp`, `package.json`, and `tspconfig.yaml` are
committed.
